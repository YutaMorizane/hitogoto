## プロジェクト概要

### サービス名

HITOGOTO ～しらんけどエージェント～

### コンセプト

会議には立場の違いから生まれる摩擦がつきものである。言うべきことが言えない、言ったら責任を負わされる——HITOGOTOはその責任をAIに引き受けさせることで、発言者の心理的負担を構造的に解消するWebアプリケーションである。批判されればAIのせい、称賛されれば人間の手柄。

### ハッカソンテーマとの接続

「人をダメにするソフトウェア・サービス」— 本来人間が負うべき責任をAIに肩代わりさせることで、責任逃れをするダメ人間に近づいていく点がテーマとマッチする。

### キャッチコピー

- 「責任はAIのせい。でも、手柄は人間のもの('ω')ノ」
- 「人間関係のストレスからの解放。明日から仕事に行きたくてしょうがなくなる会社を作る！」

## ビジネスインテント

### 解決する課題

#### 課題の構造（心理的力学）

人間関係における会議の場では、「聞く側・承認者」が強い立場に、「言う側・承認を求める側」が弱い立場になる。この非対称な力学が、発言者に以下のストレスを生む：

- **言いづらいストレス**: 言わなければならないが、関係性を損ねるリスクがある
- **批判されるかもしれないストレス**: 自分の評価や立場に影響する可能性がある
- **責任を負わされるストレス**: 発言内容に対する責任が個人に帰属する

#### 具体的なストレス場面

- 後輩を指導する際に厳しく言わなければならない場面
- 声が大きい人（物理的・心理的）と交渉する場面
- 不具合報告で責められやすい弱い立場に置かれる場面
- 初対面で相手が分からず不安な場面
- 会議で皆が無反応で責任を持ってもらえない場面

#### 対象となる会議体

- 承認会議（予算承認、設計レビュー、リリース判定等）
- 不具合報告会議（障害報告、品質レビュー等）
- 提案・企画会議（新規施策の提案、改善提案等）
- 指導・フィードバック面談

### なぜAIで解決できるのか

本サービスの核心は、**心理的立場の構造的転換**にある。

人間同士の会話では「聞く側＝強い立場」「言う側＝弱い立場」という力学が固定される。しかし、AIが代弁者として介在すると、以下の構造転換が起きる：

1. **AIが「言う側」を引き受ける** → ユーザーは「AIに指示を出す側（承認者）」の立場になる
2. **相手もAIに対しては「聞く側」になる** → AIの発言に対して人間は常に上位の立場を取れる
3. **責任帰属がAIに移る** → 間違っていてもAIのせいにでき、正しければ人間の手柄になる

この構造により、人間の代理人（秘書や仲介者）では実現できない「責任の完全な切り離し」が可能になる。人間の仲介者は自身も責任を負うため、依頼者のストレスを完全には吸収できない。AIは責任を「引き受けた形」にできるため、心理的負担をゼロに近づけられる。

### 既存代替手段との差別化

| 観点 | 既存ツール（Otter.ai、Copilot等） | HITOGOTO |
|---|---|---|
| 主な機能 | 会議の記録・要約・文字起こし | 代弁・責任帰属切替・即時リカバリー |
| ユーザーの立場 | 発言者のまま（記録されるだけ） | AIに代弁させることで承認者の立場に転換 |
| ストレス軽減 | 議事録作成の手間を軽減 | 対人ストレスそのものを構造的に軽減 |
| 責任帰属 | 発言者に帰属したまま | AIに帰属を切り替え可能 |
| リアルタイム性 | 記録は事後的 | 会議中にリアルタイムで介入・代弁 |
| 独自価値 | 生産性向上 | 心理的安全性の構造的担保 |

## 機能要件

### FR-001: AI代弁機能

ユーザーが言いづらい内容をAIが代弁する機能である。ユーザーが入力または選択した内容を、AIが「AI発信」として明示した上で発言する。ユーザーは最終上書き権限を持ち、配信前後に内容を確認・訂正できる。AIは会議参加者の特性（役職、性格傾向、関係性等）を考慮し、発言内容・表現・トーンを動的に調整する。

- FR-001-1: ユーザーがテキスト入力でAIに代弁させたい内容を指定できる
- FR-001-2: AIが文脈を理解し、適切な表現に変換して代弁案を生成する
- FR-001-3: ユーザーが代弁案を承認してから発信される（承認フロー）
- FR-001-4: 代弁内容は「AIによる発言」であることが明示される
- FR-001-5: Amazon Bedrock（Claude）を使用してAI生成を行う
- FR-001-6: 配信済みの代弁内容を訂正・上書きできる（最終上書き権限）
- FR-001-7: 代弁案の編集・カスタマイズが承認前に可能である
- FR-001-8: AI発言後に「この発言の責任者: AI」と明示的に表示される
- FR-001-9: ユーザーが後から「自分の発言にする」と責任を引き取れる（責任帰属の双方向切替）
- FR-001-10: AI代弁時に「※これはAIの見解です。しらんけど。」の免責表示を付与する
- FR-001-11: 会議参加者のプロファイル（役職、性格傾向、関係性、過去のやり取り）に基づき、発言内容・表現・トーンを動的に調整する
- FR-001-12: 参加者が複数いる場合、主たる発言対象者（宛先）を指定でき、その人物に最適化された表現を生成する
- FR-001-13: テキスト入力に加え、音声ウィスパー入力（小声での音声入力）および定型文クイック選択による代弁内容の指定が可能である
- FR-001-14: 自動承認モードを提供し、ユーザーが事前に有効化した場合はAI代弁案を確認なしで即発信できる

### FR-002: リアルタイム音声文字起こし

会議中の音声をリアルタイムでテキストに変換する機能である。

- FR-002-1: ブラウザのマイク入力（MediaDevices API）で自分の音声を取得する
- FR-002-2: Screen Capture API（getDisplayMedia）で相手の音声（システム音声共有）を取得する
- FR-002-3: Amazon Transcribe Streamingでリアルタイム文字起こしを行う
- FR-002-4: 文字起こし結果をリアルタイムでUI上に表示する
- FR-002-5: 話者識別（自分/相手）を行う

### FR-003: AIフォロー・提案・即時リカバリー機能

会議中の文脈に基づき、AIがフォローアップ・提案・即時リカバリーを行う機能である。発言ミスや誤解が生じた場合にリアルタイムで修正案を提示し、議論の軌道修正を支援する。

- FR-003-1: 会議の文脈を分析し、質問への一次回答案を生成する
- FR-003-2: リスクのある表現の緩和案を提示する
- FR-003-3: 補足情報や反論への対応案を提示する
- FR-003-4: 提案はユーザー承認後に送信される
- FR-003-5: 発言ミス・誤解発生時に即時リカバリー案（言い換え・撤回・補足）を提示する
- FR-003-6: 相手の反応（反論・困惑等）を検知し、自動的にフォロー案を生成する

### FR-004: AI提案モード切替

AIの動作モードを切り替える機能である。

- FR-004-1: 代弁モード（ユーザーの代わりにAIが発言）
- FR-004-2: フォローモード（AIが補足・フォローを提案）
- FR-004-3: 言い換えモード（ユーザーの発言を適切な表現に変換）
- FR-004-4: しらんけどモード（AIがより大胆・率直な発言を行う。責任は完全にAIに帰属し、ユーザーは「AIが勝手に言った」と主張できる）
- FR-004-5: モード切替はワンクリックで即座に行える
- FR-004-6: 各モードの責任帰属レベルが明示される（代弁: ユーザー寄り、しらんけど: AI完全帰属）
- FR-004-7: AIが会議の文脈・状況に応じて最適なモードを自動推奨し、ユーザーはワンタップで推奨モードに切り替えられる

### FR-005: ユーザー認証

Amazon Cognitoを使用したユーザー認証機能である。

- FR-005-1: ユーザー登録（サインアップ）機能
- FR-005-2: ログイン/ログアウト機能
- FR-005-3: セッション管理
- FR-005-4: パスワードリセット機能

### FR-006: WebSocketリアルタイム通信

API Gateway WebSocket APIを使用したリアルタイム通信機能である。

- FR-006-1: WebSocket接続の確立と維持
- FR-006-2: AI応答のリアルタイム配信
- FR-006-3: 接続断時の自動再接続
- FR-006-4: 接続状態の表示

### FR-007: 会議セッション管理

会議の開始・終了・履歴管理・参加者プロファイル・会議後サマリ生成機能である。

- FR-007-1: 会議セッションの開始（会議名、参加者情報の設定）
- FR-007-2: 会議セッションの終了
- FR-007-3: 会議履歴の保存（DynamoDB）
- FR-007-4: 過去の会議履歴の閲覧
- FR-007-5: 参加者プロファイルの簡易入力（名前、役職、関係性、コミュニケーション傾向等）
- FR-007-6: 会議終了後に意思決定ログを自動生成する
- FR-007-7: 会議終了後に次アクション（TODO）リストを自動生成する
- FR-007-8: 会議サマリ（要点・決定事項・未解決事項）を自動生成する

### FR-012: ダメ人間度メーター

AI代弁への依存度を可視化し、「人をダメにする」テーマを体験レベルで表現する機能である（Phase 1）。

- FR-012-1: AI代弁に頼った回数の累積表示
- FR-012-2: 「自分で言えたはずの発言」をAIに任せた割合の算出
- FR-012-3: ダメ人間度のレベル表示（例: ★☆☆☆☆ → ★★★★★）
- FR-012-4: 会議終了後に「今日もAIのおかげで乗り切りました。ダメ人間度+1」のような演出表示
- FR-012-5: 累積ダメ人間度の推移グラフ表示
- FR-012-6: 責任引き受け履歴（AIがどれだけ責任を肩代わりしたか）の可視化

### FR-008: パーソナルデータベース

ユーザーの個人情報・嗜好・過去の会議データを蓄積する機能である（Phase 2）。

- FR-008-1: 過去の会議メモ・決定事項の蓄積
- FR-008-2: 個人の語彙嗜好・成功パターンの学習
- FR-008-3: 次回提案への反映

### FR-009: 指標管理・ダッシュボード

ユーザーの会議パフォーマンスを可視化する機能である（Phase 2）。

- FR-009-1: 目標設定（発言回数、合意形成率等）
- FR-009-2: 達成度のダッシュボード表示
- FR-009-3: 会議後レポートの自動生成

### FR-010: ゲーミフィケーション

ミッション/バッジで行動を促進し、会議参加のモチベーションを高める機能である（Phase 2）。

- FR-010-1: 会議での行動に応じたミッション（例: 「今日は3回発言する」）の提示
- FR-010-2: ミッション達成時のバッジ付与
- FR-010-3: 会議中の簡易HUDで次アクション・ミッション進捗を表示
- FR-010-4: 累積実績の可視化

### FR-011: 表現自動変換

ユーザーの嗜好と言語スタイルに合わせて文体・丁寧さ・長さを自動調整する機能である（Phase 2、パーソナルDB連動）。

- FR-011-1: ユーザーの過去の発言パターンから文体嗜好を学習する
- FR-011-2: 相手の役職・関係性に応じた丁寧さレベルを自動調整する
- FR-011-3: 発言の長さ（簡潔/詳細）をコンテキストに応じて調整する

### FR-013: 依存度エスカレーション

使い続けるほどAIへの依存が深まる段階的設計により、「人をダメにする」体験を強化する機能である（Phase 2）。

- FR-013-1: レベル1 — AIが提案し、ユーザーが承認する（現Phase 1の基本動作）
- FR-013-2: レベル2 — AIが自動で発言し、ユーザーは事後確認のみ
- FR-013-3: レベル3 — AIが会議全体を代行し、ユーザーは結果だけ確認する
- FR-013-4: レベル4 — 「あなたはもう会議に出なくていいですよ」とAIが提案する（究極のダメ人間到達点）
- FR-013-5: 依存レベルの自動昇格提案（利用頻度に応じてAIが「もっと任せませんか？」と誘惑する）

## ユーザーロール

### 言う側・主催者

会議や審議の場で提案・説明を行い、議事進行と意思決定のリードを担う人。AI代弁機能の主要ユーザーである。

### 聞く側・承認者

提案を評価し、承認または差戻しを判断する立場。上位者や決裁権を持つマネージャーである。

### オブザーバ

会議に同席するが主導権を持たない参加者。発言促進やアクション確認の対象である。

## Phase 1 スコープ（MVP）

Phase 1で実装する機能要件：

- FR-001: AI代弁機能（最重要 — 配信後訂正・上書き権限・責任帰属双方向切替を含む）
- FR-002: リアルタイム音声文字起こし
- FR-003: AIフォロー・提案・即時リカバリー機能
- FR-004: AI提案モード切替（しらんけどモードを含む）
- FR-005: ユーザー認証
- FR-006: WebSocketリアルタイム通信
- FR-007: 会議セッション管理（参加者プロファイル入力・会議後サマリ生成を含む）
- FR-012: ダメ人間度メーター（テーマ適合性の核心）

Phase 2以降に延期する機能要件：

- FR-008: パーソナルデータベース
- FR-009: 指標管理・ダッシュボード
- FR-010: ゲーミフィケーション（ミッション/バッジ）
- FR-011: 表現自動変換（文体・丁寧さ・長さの自動調整）
- FR-013: 依存度エスカレーション（段階的AI依存深化設計）

## デモシナリオ（想定時間: 3分）

1. 会議中にユーザーが言いづらい指摘を「しらんけどモード」でAIに代弁させる
2. AIの発言に対して相手が反論 → AIが即時リカバリー案を提示（「※AIの見解です。しらんけど。」表示付き）
3. ユーザーが承認し、AIが責任を引き受けた形で議論が前進する
4. 会議終了後、ダッシュボードに「今日もAIのおかげで乗り切りました。ダメ人間度+1 ★★★☆☆」と表示される
