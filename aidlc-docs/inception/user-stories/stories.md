# ユーザーストーリー

## 凡例

- **優先度**: P1（最高）〜 P4（低）— ユーザー価値の高い順
- **Phase**: 実装フェーズ（Phase 1 / Phase 2 / Phase 3）
- **ペルソナ**: P-001（主催者）/ P-002（承認者）/ P-003（オブザーバ）/ 共通

---

## Phase 1 ストーリー（MVP）

### 主催者ストーリー（P-001: 田中 健太）

#### US-001: AI代弁案の生成

**ロール**: 主催者
**関連FR**: FR-001
**優先度**: P1

As a 主催者,
I want to 言いづらい内容をテキスト入力してAIに代弁案を生成してもらう,
So that 自分の言葉で直接言うストレスを回避できる.

##### 受け入れ基準

- [ ] AC-1: テキスト入力欄に内容を入力し送信すると、5秒以内にAI代弁案が表示される
- [ ] AC-2: 代弁案は会議の文脈（直前の発言内容）を考慮した表現になっている
- [ ] AC-3: 代弁案が空文字や意味不明な内容でないことが検証される
- [ ] AC-4: Amazon Bedrock（Claude）を使用して生成される

#### US-002: 代弁案の承認と発信

**ロール**: 主催者
**関連FR**: FR-001
**優先度**: P1

As a 主催者,
I want to AI代弁案を確認・編集してから承認し発信する,
So that 意図しない内容が発信されることを防げる.

##### 受け入れ基準

- [ ] AC-1: 代弁案が表示された状態で「承認」ボタンを押すと発信される
- [ ] AC-2: 承認前に代弁案のテキストを編集できる
- [ ] AC-3: 「却下」ボタンで代弁案を破棄し、再生成を依頼できる
- [ ] AC-4: 発信された内容に「※AIの見解です。しらんけど。」の免責表示が付与される

#### US-003: 責任帰属の双方向切替

**ロール**: 主催者
**関連FR**: FR-001
**優先度**: P1

As a 主催者,
I want to AI発言の責任帰属を「AI責任」と「自分の発言」の間で切り替える,
So that 称賛された場合は自分の手柄にし、批判された場合はAIのせいにできる.

##### 受け入れ基準

- [ ] AC-1: AI発言後に「この発言の責任者: AI」と表示される
- [ ] AC-2: ユーザーが「自分の発言にする」ボタンを押すと責任帰属が切り替わる
- [ ] AC-3: 責任帰属の変更履歴が記録される
- [ ] AC-4: 切替操作はワンクリックで完了する

#### US-004: しらんけどモードでの大胆発言

**ロール**: 主催者
**関連FR**: FR-004
**優先度**: P1

As a 主催者,
I want to 「しらんけどモード」に切り替えてAIにより大胆・率直な発言をさせる,
So that 自分では絶対に言えない本音をAI経由で伝えられる.

##### 受け入れ基準

- [ ] AC-1: モード切替UIで「しらんけどモード」をワンクリックで選択できる
- [ ] AC-2: しらんけどモードでは通常モードより率直・大胆な表現が生成される
- [ ] AC-3: 発信時に「※AIが勝手に言いました。しらんけど。」の免責表示が付与される
- [ ] AC-4: 責任帰属が「AI完全帰属」として明示される

#### US-005: 配信済み内容の訂正

**ロール**: 主催者
**関連FR**: FR-001
**優先度**: P2

As a 主催者,
I want to 配信済みのAI代弁内容を後から訂正・上書きする,
So that 誤った内容が発信された場合でも修正できる.

##### 受け入れ基準

- [ ] AC-1: 配信済みの発言一覧から訂正対象を選択できる
- [ ] AC-2: 訂正内容を入力し「更新」すると、相手側にも訂正が反映される
- [ ] AC-3: 訂正履歴が記録され、元の内容と訂正後の内容が確認できる

#### US-006: 即時リカバリー案の受領

**ロール**: 主催者
**関連FR**: FR-003
**優先度**: P1

As a 主催者,
I want to 相手が反論・困惑した際にAIから即時リカバリー案を受け取る,
So that 議論が停滞せず、軌道修正できる.

##### 受け入れ基準

- [ ] AC-1: 相手の反論・困惑を検知すると3秒以内にリカバリー案が表示される
- [ ] AC-2: リカバリー案は「言い換え」「撤回」「補足」の3パターンから選択できる
- [ ] AC-3: 選択したリカバリー案は承認後に発信される

#### US-028: AIによる質問応答・表現緩和・補足提案

**ロール**: 主催者
**関連FR**: FR-003
**優先度**: P2

As a 主催者,
I want to 会議中に質問への一次回答案、リスクのある表現の緩和案、補足情報をAIから提案してもらう,
So that 即座に適切な応答ができ、発言の質を高められる.

##### 受け入れ基準

- [ ] AC-1: 相手から質問を受けた際に、5秒以内にAIが一次回答案を提示する
- [ ] AC-2: ユーザーの発言にリスクのある表現が含まれる場合、緩和案が自動提示される
- [ ] AC-3: 議論の流れに応じて補足情報や反論への対応案が提示される
- [ ] AC-4: 提案はユーザーが承認してから発信される（承認フロー適用）

#### US-007: 会議セッションの開始と参加者設定

**ロール**: 主催者
**関連FR**: FR-007
**優先度**: P2

As a 主催者,
I want to 会議セッションを開始し参加者のプロファイルを設定する,
So that AIが参加者の特性を考慮した代弁案を生成できる.

##### 受け入れ基準

- [ ] AC-1: 会議名を入力して新規セッションを開始できる
- [ ] AC-2: 参加者の名前・役職・関係性・コミュニケーション傾向を入力できる
- [ ] AC-3: 設定した参加者情報がAI代弁案の生成に反映される
- [ ] AC-4: 会議終了ボタンを押すとセッションが終了し、会議データが保存される

#### US-008: 会議後サマリの確認

**ロール**: 主催者
**関連FR**: FR-007
**優先度**: P2

As a 主催者,
I want to 会議終了後に意思決定ログ・次アクション・サマリを自動生成してもらう,
So that 会議の成果を整理する手間を省ける.

##### 受け入れ基準

- [ ] AC-1: 会議終了ボタンを押すと30秒以内にサマリが生成される
- [ ] AC-2: サマリには「要点」「決定事項」「未解決事項」「次アクション」が含まれる
- [ ] AC-3: 生成されたサマリを編集・保存できる
- [ ] AC-4: 過去の会議サマリを一覧から閲覧できる

#### US-027: 参加者に応じた発言内容の動的調整

**ロール**: 主催者
**関連FR**: FR-001, FR-007
**優先度**: P1

As a 主催者,
I want to 会議に出ている参加者の特性（役職、性格傾向、関係性）に応じてAIが発言内容・表現・トーンを自動調整する,
So that 相手に合わせた最適な伝え方で代弁してもらえる.

##### 受け入れ基準

- [ ] AC-1: 会議セッション開始時に設定した参加者プロファイルがAI代弁案の生成に反映される
- [ ] AC-2: 同じ内容でも、宛先の参加者が異なれば表現・トーンが変化する（例: 上司向けは丁寧、同僚向けはカジュアル）
- [ ] AC-3: 参加者が複数いる場合、主たる発言対象者（宛先）を選択できる
- [ ] AC-4: 同一会議セッション内での参加者の反応傾向が蓄積され、会議中の調整精度が向上する（会議をまたいだ蓄積はPhase 2で実現）

### 承認者ストーリー（P-002: 鈴木 美咲）

#### US-009: フィードバックのAI代弁

**ロール**: 承認者
**関連FR**: FR-001, FR-004
**優先度**: P2

As a 承認者,
I want to 差戻し理由や厳しいフィードバックをAIに代弁させる,
So that 部下のモチベーションを下げずに率直な指摘ができる.

##### 受け入れ基準

- [ ] AC-1: フィードバック内容を入力するとAIが柔らかい表現に変換して代弁案を生成する
- [ ] AC-2: 代弁案には差戻し理由が構造化されて含まれる（不足情報・修正期限・責任者）
- [ ] AC-3: 承認者も「しらんけどモード」を使用できる

#### US-010: 承認・差戻しの構造化記録

**ロール**: 承認者
**関連FR**: FR-007
**優先度**: P2

As a 承認者,
I want to 承認・差戻しの判断を構造化して記録・共有する,
So that 決定内容が明確で後続タスクがスムーズに進む.

##### 受け入れ基準

- [ ] AC-1: 「承認」「差戻し」ボタンで判断を記録できる
- [ ] AC-2: 差戻し時は不足情報・修正期限・責任者を入力するフォームが表示される
- [ ] AC-3: 判断内容が会議サマリに自動反映される

#### US-011: 会議サマリの確認と承認

**ロール**: 承認者
**関連FR**: FR-007
**優先度**: P3

As a 承認者,
I want to 会議後に生成されたサマリを確認し、内容に問題がないか承認する,
So that 正確な記録が残り、認識齟齬を防げる.

##### 受け入れ基準

- [ ] AC-1: 会議終了後にサマリ確認の通知を受け取る
- [ ] AC-2: サマリ内容に対してコメント・修正を追加できる
- [ ] AC-3: 承認ボタンで最終確定できる

### 共通ストーリー

#### US-012: ユーザー登録・ログイン

**ロール**: 共通（主催者・承認者）
**関連FR**: FR-005
**優先度**: P2

As a ユーザー,
I want to アカウントを登録しログインする,
So that 自分専用の環境でサービスを利用できる.

##### 受け入れ基準

- [ ] AC-1: メールアドレスとパスワードでサインアップできる
- [ ] AC-2: 登録後にメール認証が完了するとログイン可能になる
- [ ] AC-3: ログイン後にダッシュボード画面が表示される
- [ ] AC-4: パスワードリセット機能が利用できる
- [ ] AC-5: ログインセッションが維持され、トークン期限切れ時に自動リフレッシュされる

#### US-013: リアルタイム音声文字起こし

**ロール**: 共通（主催者・承認者）
**関連FR**: FR-002
**優先度**: P2

As a ユーザー,
I want to 会議中の音声がリアルタイムでテキスト化される,
So that AIが会議の文脈を理解して適切な代弁案を生成できる.

##### 受け入れ基準

- [ ] AC-1: マイク入力の許可後、自分の音声が2秒以内にテキスト化される
- [ ] AC-2: Screen Capture APIで共有した相手の音声もテキスト化される
- [ ] AC-3: 話者識別（自分/相手）が正しく行われる
- [ ] AC-4: 文字起こし結果がリアルタイムでUI上に表示される
- [ ] AC-5: 音声文字起こしにAmazon Transcribe Streamingが使用される

#### US-014: WebSocket接続と状態管理

**ロール**: 共通（主催者・承認者）
**関連FR**: FR-006
**優先度**: P2

As a ユーザー,
I want to 安定したリアルタイム通信が維持される,
So that AI応答が遅延なく受信できる.

##### 受け入れ基準

- [ ] AC-1: 会議開始時にWebSocket接続が自動確立される
- [ ] AC-2: 接続状態（接続中/切断/再接続中）がUIに表示される
- [ ] AC-3: 接続断時に自動再接続が試行される
- [ ] AC-4: AI応答のレイテンシが500ms以内である
- [ ] AC-5: AI応答（代弁案、リカバリー案、フォロー案）がWebSocket経由でリアルタイム配信される

#### US-015: ダメ人間度メーターの表示

**ロール**: 共通（主催者・承認者）
**関連FR**: FR-012
**優先度**: P1

As a ユーザー,
I want to AI代弁への依存度が「ダメ人間度」として可視化される,
So that 「人をダメにする」体験を自覚的に楽しめる.

##### 受け入れ基準

- [ ] AC-1: AI代弁を利用するたびにダメ人間度カウンターが増加する
- [ ] AC-2: ダメ人間度がレベル表示される（★☆☆☆☆ → ★★★★★）
- [ ] AC-3: 会議終了後に「今日もAIのおかげで乗り切りました。ダメ人間度+N」と演出表示される
- [ ] AC-4: 累積ダメ人間度の推移がグラフで確認できる
- [ ] AC-5: 責任引き受け履歴（AIが肩代わりした回数・内容）が一覧表示される
- [ ] AC-6: 「自分で言えたはずの発言」をAIに任せた割合が算出・表示される

#### US-016: AI提案モードの切替

**ロール**: 共通（主催者・承認者）
**関連FR**: FR-004
**優先度**: P1

As a ユーザー,
I want to AIの動作モード（代弁/フォロー/言い換え/しらんけど）をワンクリックで切り替える,
So that 状況に応じた最適なAI支援を受けられる.

##### 受け入れ基準

- [ ] AC-1: 4つのモード（代弁/フォロー/言い換え/しらんけど）がUIに表示される
- [ ] AC-2: ワンクリックで即座にモードが切り替わる
- [ ] AC-3: 現在のモードと責任帰属レベルが明示される
- [ ] AC-4: モード切替後、次のAI応答から新モードが適用される

#### US-029: クイック入力（定型文・音声ウィスパー入力）

**ロール**: 共通（主催者・承認者）
**関連FR**: FR-001
**優先度**: P2

As a ユーザー,
I want to テキスト入力以外に、音声ウィスパー入力や定型文クイック選択でAIに代弁内容を指定する,
So that 会議中にキーボードを使わず素早く指示を出せる.

##### 受け入れ基準

- [ ] AC-1: マイクボタンを押して小声で話すと、その内容がAIへの代弁指示として認識される
- [ ] AC-2: よく使う指示（「反論して」「同意して」「質問して」等）が定型文ボタンとして表示される
- [ ] AC-3: 定型文ボタンはワンタップで選択でき、即座に代弁案生成が開始される
- [ ] AC-4: 音声ウィスパー入力は会議音声と区別して処理される（入力用マイクの分離または押下中のみ認識）

#### US-030: 自動承認モード

**ロール**: 共通（主催者・承認者）
**関連FR**: FR-001
**優先度**: P2

As a ユーザー,
I want to 自動承認モードを有効にして、AI代弁案を確認なしで即発信する,
So that 会議の流れが速い場面でも操作が間に合う.

##### 受け入れ基準

- [ ] AC-1: 設定画面または会議中UIで「自動承認モード」のON/OFFを切り替えられる
- [ ] AC-2: 自動承認モードON時、AI代弁案は生成後に即発信される（承認ステップをスキップ）
- [ ] AC-3: 自動承認モードON時、発信後に「取り消し」ボタンが3秒間表示される（誤発信防止）
- [ ] AC-4: 自動承認モードの状態がUIに常時表示される（誤操作防止）

#### US-031: AIによるモード自動推奨

**ロール**: 共通（主催者・承認者）
**関連FR**: FR-004
**優先度**: P3

As a ユーザー,
I want to AIが会議の状況に応じて最適なモードを自動推奨してくれる,
So that どのモードを使えばいいか迷わずに済む.

##### 受け入れ基準

- [ ] AC-1: 会議の文脈（相手の発言トーン、議題の種類）に基づきAIが推奨モードを提示する
- [ ] AC-2: 推奨モードはUIにハイライト表示され、ワンタップで切り替えられる
- [ ] AC-3: 推奨を無視して手動でモードを選択することも可能である
- [ ] AC-4: デフォルトモードを事前に設定でき、会議開始時はデフォルトモードで起動する

#### US-032: 透明性・同意管理

**ロール**: 共通（主催者・承認者）
**関連FR**: NFR-006
**優先度**: P2

As a ユーザー,
I want to 会議の録音・文字起こしに関する同意管理と透明性が確保される,
So that 参加者のプライバシーが守られ、安心してサービスを利用できる.

##### 受け入れ基準

- [ ] AC-1: 会議の録音・文字起こし開始時に参加者への通知メッセージが表示される
- [ ] AC-2: AI代弁時は相手側にも「AIによる発言」であることが明示される
- [ ] AC-3: 会議データの共有範囲（自分のみ/参加者全員/チーム）をユーザーが設定できる
- [ ] AC-4: 会議データの保存期間（30日/90日/無期限等）をユーザーが設定できる
- [ ] AC-5: 参加者の同意状態（同意済み/未同意）が記録・表示される

#### US-033: UIデザイン基準（Serendie DS・HUD形式）

**ロール**: 共通（主催者・承認者）
**関連FR**: NFR-004
**優先度**: P2

As a ユーザー,
I want to 統一的なデザインシステムに基づくUIと、会議中は最小限のHUD表示で操作できる,
So that 直感的に操作でき、会議に集中しながらサービスを利用できる.

##### 受け入れ基準

- [ ] AC-1: 全画面がSerendie Design Systemのコンポーネントで構成される
- [ ] AC-2: 会議中はHUD形式（オーバーレイ表示）で最小限の情報のみ表示される
- [ ] AC-3: HUDには現在のモード、接続状態、直近のAI提案のみが表示される
- [ ] AC-4: HUDの表示/非表示をワンクリックで切り替えられる
- [ ] AC-5: レスポンシブデザインに対応し、デスクトップ・タブレットで利用可能である

## Phase 2 ストーリー

### オブザーバストーリー（P-003: 佐藤 翔太）

#### US-017: 発言タイミングの促し

**ロール**: オブザーバ
**関連FR**: FR-010
**優先度**: P3

As a オブザーバ,
I want to 適切な発言タイミングでAIから促しを受ける,
So that 会議で存在感を出し、無責任な不参加を避けられる.

##### 受け入れ基準

- [ ] AC-1: 一定時間発言がない場合にAIから発言促しの通知が表示される
- [ ] AC-2: 促しには具体的な発言案（質問・意見・確認）が含まれる
- [ ] AC-3: 促しを無視した場合の追いタスク発行機能がある

#### US-018: 会議要約とアクション確認

**ロール**: オブザーバ
**関連FR**: FR-007, FR-010
**優先度**: P3

As a オブザーバ,
I want to 議題終了時に要約とアクションオーナーを確認する,
So that 自分の担当アクションを明確に把握できる.

##### 受け入れ基準

- [ ] AC-1: 議題ごとに要約が自動生成される
- [ ] AC-2: アクションオーナーが明示される
- [ ] AC-3: 自分が担当するアクションがハイライト表示される

### パーソナルデータベース

#### US-019: 会議データの蓄積と学習

**ロール**: 共通
**関連FR**: FR-008
**優先度**: P3

As a ユーザー,
I want to 過去の会議データが蓄積され、AIの提案精度が向上する,
So that 使い続けるほど自分に合った代弁案が生成される.

##### 受け入れ基準
