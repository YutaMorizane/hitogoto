# ペルソナ定義

## P-001: 田中 健太（主催者ペルソナ）

| 項目 | 内容 |
| --- | --- |
| 年齢 | 32歳 |
| 役職 | ITプロジェクトリーダー |
| 経験年数 | 入社8年目 |
| 企業規模 | 200人規模のSIer |
| 性格特性 | 技術力は高いがコミュニケーションに苦手意識あり。論理的だが感情表現が苦手 |
| 主な会議 | 設計レビュー、進捗報告、障害報告、予算承認 |
| ストレス源 | 上司への報告時に批判されることへの不安。不具合報告で責められる立場に置かれること |
| 期待する価値 | 関係性を損なわず率直な提案ができる。AIのせいにして心理的負担を軽減できる |
| ITリテラシー | 高い（開発者） |

### 利用シーン

- 設計レビューで問題点を指摘する際にAIに代弁させる
- 障害報告会議で原因説明をAIにフォローしてもらう
- 予算超過の報告を「しらんけどモード」で伝える

## P-002: 鈴木 美咲（承認者ペルソナ）

| 項目 | 内容 |
| --- | --- |
| 年齢 | 45歳 |
| 役職 | 開発部門マネージャー |
| 経験年数 | 入社20年目 |
| 企業規模 | 200人規模のSIer |
| 性格特性 | 決断力があるが、部下への厳しい指摘に心理的負担を感じている |
| 主な会議 | 設計レビュー（承認側）、予算承認、人事面談 |
| ストレス源 | 差戻し時に部下のモチベーションを下げてしまうこと。厳しく言わなければならない責任 |
| 期待する価値 | 率直な指摘でも関係を損ねない言い回しで伝えられる。差戻し理由が構造化される |
| ITリテラシー | 中程度（管理職） |

### 利用シーン

- 設計レビューで差戻し理由をAIに構造化して伝えてもらう
- フィードバック面談で改善点をAI経由で柔らかく伝える
- 承認・差戻しの判断根拠を自動サマリ化する

## P-003: 佐藤 翔太（オブザーバペルソナ）

| 項目 | 内容 |
| --- | --- |
| 年齢 | 26歳 |
| 役職 | ジュニアエンジニア |
| 経験年数 | 入社3年目 |
| 企業規模 | 200人規模のSIer |
| 性格特性 | 真面目だが発言に自信がない。会議で存在感を出せずに悩んでいる |
| 主な会議 | 設計レビュー（同席）、チーム定例、勉強会 |
| ストレス源 | 発言すべきタイミングが分からない。的外れなことを言って恥をかきたくない |
| 期待する価値 | 適切なタイミングで発言を促してもらえる。会議内容を短時間で把握できる |
| ITリテラシー | 高い（若手開発者） |

### 利用シーン（Phase 2）

- 会議中にAIから発言タイミングの促しを受ける
- 議題終了時に要約とアクションオーナーを確認する
- 自分の担当アクションを明確化する
